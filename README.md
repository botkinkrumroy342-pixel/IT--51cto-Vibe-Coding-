五阶段全栈闭环——从意图到可运行系统的技术实现
意图和规格确定之后，Vibe Coding 的全栈开发进入工程实现阶段。这条技术链路被验证为五个阶段的迭代闭环，覆盖从需求原型到线上部署的完整路径。

阶段一：意图定义与架构约束
开发者以自然语言描述产品目标、页面交互、数据结构、权限规则和技术栈选型，同时给出硬性约束：数据库选型、后端框架、前端组件库、性能要求和安全规则。这个阶段产出的不是代码，而是一份让 AI 可独立开展开发的规格文档。核心设计原则是文档详尽度需达到“AI 读取后可独立开展开发”的标准，消除歧义性描述；明确 MVP 阶段核心功能范围，非核心功能预留桩函数或通过特性开关控制，避免范围蔓延；项目结构采用模块化设计，严格规避单体巨文件，保障并行开发可行性。

阶段二：全栈代码批量生成
AI 编码智能体（如 Codex、Cursor 内置 Agent）一次性生成前端页面、组件、路由、后端接口、数据模型、数据库迁移脚本、环境变量、Docker 配置和部署脚本。这不再是单片段代码补全，而是跨目录、跨层的多文件工程输出。Vibe Coding 生成的代码与无代码平台有本质区别：无代码平台输出封闭配置，而 Vibe Coding 生成的是原生可读、可修改、可独立部署的完整源码，可自由二次开发、接入 CI/CD、进行工程化迭代。

阶段三：本地沙盒运行与效果观测
在隔离沙盒环境启动完整应用，访问前端页面、调用后端接口，观察页面渲染、接口返回、数据库读写和报错日志。开发者重点验证功能行为，而不是逐行阅读源码。这一步的关键技术是沙盒隔离——代码执行环境与宿主系统分离，避免 AI 生成的命令直接影响开发机。同时，沙盒环境需要提供完整的运行反馈，包括渲染结果、接口响应和错误堆栈，这些反馈将作为下一阶段迭代的输入。

阶段四：反馈驱动迭代修复
将运行报错、UI 不符合预期、逻辑缺陷和性能问题以自然语言反馈给 AI，由 AI 自动修改多文件代码、修复 bug、调整样式与接口逻辑，反复循环。这个阶段的工程核心是建立 AI 能够“自助验证”的机制。具体的做法是引入反馈闭环——通过构建 CLI 模拟测试平台、TDD 和预设问题清单重构，在无需人工干预下实现 AI 自主编写、测试、修复与优化代码。其中的核心在于回归 TDD（测试驱动开发）：先写失败测试，再让 AI 修到通过。测试就是“校验码”，即使你看不懂每一行实现，只要测试通过，代码就大概率正确。

阶段五：代码审计、测试与上线部署
完成功能迭代后，人工做架构评审和安全审计，补充单元测试、集成测试，配置 CI/CD 流水线，完成构建与部署。这个阶段不可被 AI 替代的部分包括：登录、支付、权限、数据删除等关键路径必须人工审查；安全底线必须人工把关，防注入、XSS、CSRF 和越权不能依赖前端校验。质量保障的层级从单元测试（局部逻辑正确）、集成测试（模块协作正确）、E2E（用户路径正确）到 lint、typecheck、build 和 diff 审查，形成完整的验证链条。

五个阶段不是线性的，而是持续迭代的闭环。快速原型优先，验证优先，在迭代中收敛质量，而非一次性写出完美代码，这是 Vibe Coding 全栈开发的核心特征。
